# mock-upstream 用户个人中心（mock-upstream-console）变更提案

## 动机（Why）

现有 mock-upstream 是"自动演绎"模式：应用启动后 `DemoRunner` 自动顺序跑完充值、提现结算、提现取消三条故事线，全程只输出控制台日志。开发者在演示与学习时面临三个问题：

1. **黑盒自动**：启动即跑完，节奏不可控——想观察"冻结后余额如何变化"时，三条线已经全部跑完；
2. **日志即全部**：每一步只是一行 `log.info`，没有可视化上下文（当前用户是谁、处于什么状态、这笔操作对应现实世界中的什么动作）；
3. **动作无业务归属**：日志中的 `POST /deposit` 不会告诉用户"这对应现实世界中：用户转账 → 链上确认达标 → 业务系统通知入账"。

本变更将 mock-upstream 从"自动播放的录像带"改造为"手动操控的方向盘"：提供一个 **模拟用户个人中心页面**（UI 式），只暴露**用户视角**的操作（创建用户 / 发起充值 / 申请提现 / 取消提现），所有系统内部步骤（确认数推进、入账、广播、结算、解冻）收敛为一个 **「一键处理」按钮** 批量自动完成。每个 UI 操作都映射到具体用户操作与 OTX 接口，因果清晰、节奏由用户掌控。

## 设计方案（What Changes）

### 交互模型：用户操作 vs 一键处理

```
你的操作（UI 按钮）              ⚙ 一键处理自动完成（内部流程）
─────────────────────           ─────────────────────────────
[创建用户]            → 幂等开户，切换到新用户资产页
[发起充值]            → 模拟链打包交易，状态"确认中 1/12"
                                ↓ 推块至确认达标
                                → POST /deposit 入账 → "已入账"
[申请提现]            → POST /withdraw/freeze，状态"已冻结"
                                ↓ POST /withdraw/broadcast 广播
                                → POST /withdraw/{bizNo}/confirm-settle
                                → "已结算"
[取消提现]            → 状态"取消处理中"
                                ↓ POST /withdraw/{bizNo}/cancel
                                → 解冻回可用余额 → "已取消"
```

- **每笔独立触发**：每笔充值生成独立模拟交易、独立 bizNo、独立确认数展示（如 5/12）；
- **一键处理 = 批量推进所有挂起事项**：所有"确认中"充值推块至达标并入账；所有"已冻结/已广播"提现推进至结算；所有"取消处理中"提现完成解冻；
- **无定时推块**：模拟链区块仅在「一键处理」时推进，确认数演化的中间过程折叠为页面日志行；
- **操作日志**：内存环形缓冲，页面展示"业务身份 + HTTP 调用 + OTX 响应"，替代原控制台日志。

### 变更范围

**mock-upstream 模块（独立应用，端口 8004，不加入主工程 reactor）**：

1. **新增 Web 依赖**：`spring-boot-starter-web` + `spring-boot-starter-thymeleaf`（与 admin-console 技术栈一致），新增页面渲染与表单提交端点；
2. **新增内存状态注册表**（并发安全，重启即失）：
   - 用户注册表（uid → 账户摘要，支撑多用户创建与切换）；
   - 充值记录（bizNo、uid、金额、确认数、状态：`CONFIRMING` / `BOOKED`）；
   - 提现记录（bizNo、uid、金额、状态：`FROZEN` / `SETTLED` / `CANCEL_PENDING` / `CANCELLED`）；
   - 操作日志环形缓冲（页面展示）；
3. **场景编排器重构**（复用现有 `BlockchainSimulator` / `OtxClient` / 模拟交易注册逻辑）：
   - `DepositSimulator`：拆分"发起充值"（注册交易）与"确认入账"（推块至达标 → POST /deposit）两个动作；
   - `WithdrawSimulator`：拆分"申请提现"（freeze）、"标记取消"（仅改状态）与"一键处理"（broadcast → 推块 → confirm-settle / cancel）三个动作；
   - 新增 `ProcessOrchestrator`：一键处理的编排入口，遍历所有挂起事项批量推进；
4. **移除自动演绎**：删除 `DemoRunner` 启动自动执行逻辑，改为纯手动 UI 触发（保留可选的"一键自动播放完整故事线"按钮，复用现有故事线编排逻辑，作为演示捷径——非默认路径）；
5. **新增页面**：`GET /`（个人中心主页：资产卡片、充值/提现表单、记录列表、一键处理按钮、操作日志）；
6. **新增端点**：`POST /users`（创建用户）、`POST /users/{uid}/select`（切换用户）、`POST /deposits`（发起充值）、`POST /withdrawals`（申请提现）、`POST /withdrawals/{bizNo}/cancel`（取消提现）、`POST /internal/process`（一键处理）。

**OTX 主项目：零改动**（mock-upstream 仍只通过 HTTP 调用 OTX REST API，不 import 任何 OTX 内部类）。

**specs 变更**：更新 `mock-upstream` 限界上下文规范——从"自动演绎"改为"UI 手动触发 + 一键处理"。

## Capabilities（能力）

### Modified Capabilities

- `mock-upstream`：模拟上游与链上事件能力——由"启动自动演绎"改为"模拟用户个人中心 UI，手动触发业务动作，一键处理内部流程"，保持纯 HTTP 外部调用方身份。

## Impact（影响）

- **仓库结构**：仅修改 `mock-upstream/` 独立目录（pom + src），不进入 6 模块 reactor，不影响 `mvnw clean install` 主构建；
- **OTX 主项目**：零改动；
- **文档**：README「一键体验」章节同步更新（启动顺序不变：OTX :8003 → mock-upstream :8004 → 打开个人中心手动操作）。

## 非目标（Non-Goals）

- **不做真实链上交互**：仍不连真实 RPC、不广播真实交易，模拟链保持内存实现；
- **不修改 OTX 主项目**：admin-console 页面、REST 契约、应用服务均不动；
- **不持久化模拟器状态**：用户/记录/日志均为内存态，重启即失（演示工具定位不变）；
- **不做并发压力模拟**：单用户浏览器操作 + 一键处理批量推进即可，不做性能测试；
- **不做自动演绎的默认执行**：启动不再自动跑故事线；"一键自动播放"仅作为可选演示捷径。
